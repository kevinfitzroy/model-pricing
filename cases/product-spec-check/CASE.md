# CASE — product-spec-check(产品/规格核验)

> 套用 [`../../WORKFLOW.md`](../../WORKFLOW.md)。核某产品的官方规格/参数/价格,与 model-pricing 同构。

## 1. 目标 & 输入
- **目标**:把某产品(手机、显卡、云服务、SaaS 套餐……)的**官方规格/参数/价格**整理成可对比、可溯源的结构化数据;或核验某处声称的规格是否属实。
- **输入**:产品名(可选:一组待核的声称规格,或竞品列表)。

## 2. 被核验单元
- 一个单元 = **一项规格/参数/价格**(如"内存 16GB""算力 X TFLOPS""年费 $Y")。
- 精确身份(R4):精确到**型号 + 版本/SKU**(同名产品多配置价差大),逐项记参数名。

## 3. 可信来源
- **一手**:厂商官方产品页 / 官方 spec sheet / 官方定价页 / 官方文档。
- **二手(仅交叉)**:评测站、零售页、聚合参数库。
- ⚠️ 零售/经销价 ≠ 官方价;不同地区/SKU 价不同,要标清。

## 4. 产出结构
- `specs.json`(套通用 schema):每项 `subject`=型号·参数名,`kind=spec`,`fields`={value, unit, sku/variant, region},原值 + 必要的归一化,`source_type`,`evidence_ref`,`confidence`。
- 若是"核验某声称规格":加 `verdict`(supported/refuted/misleading)。
- 人读视图 `specs.csv`;可视化(可选)对比表/雷达图。

## 5. 范围边界
- 收:官方公布的客观规格/参数/价格。
- 不收:主观评测分、"体验感受"(归分析层)。

## 6. case 专属注意
- **SKU/地区/币种**:同型号多配置、多地区价 → 逐行标 variant + region + currency,别混。
- **营销话术**:"最高可达""起"这类要标清是峰值/起步值还是常态。
- **单位口径**:跑分/算力/带宽的测试条件要一并记(同参数不同测法不可比)。

## 7. 审计补充
- reviewer 抽样回官方 spec 页复核;检查有无把零售价当官方价、把营销峰值当常态、SKU/地区混淆。

## 8. 触发语
- `/factcheck product <产品名>`
