01

三阶段

每个 case 都走同一条流水线。关键在于取证与审计分离、事实与解读分离。

PHASE 01

定义

把这个 case 怎么实例化写成 CASE.md:被核验单元是什么、什么算一手来源、产出长什么样、验收标准。定义先于执行。

PHASE 02

取证

逐单元抓一手/官方来源,原文逐字存进 evidence/,再派生结构化结论,每条反向引用证据,未知留空标记。

PHASE 03

独立审计

另起独立 reviewer 逐条核 + 重抓抽样,出 REVIEW_REPORT。溯源/真实性任一不过即整体不过。

证据先行

无逐字原文证据,不落任何结论。

一手为准

官方/原始来源第一;二手只作交叉验证。

未知不猜

查不到就显式留洞,绝不估算冒充。

事实≠解读

带引用的事实与对比/判断物理分开存放。

02

八条硬规则

违反任意一条,审计判定不通过。完整版见 WORKFLOW.md。

R1
联网核实,不信记忆

对象身份/现状必须来自联网检索,不靠训练知识脑补。

R2
证据先行

每个结论都能反向指到一条逐字原文证据。

R3
一手为准

二手只作交叉验证,必须标 secondary。

R4
精确到身份

精确 id / 逐字原句 / 型号+版本,不用泛称。

R5
未知显式,不猜

查不到留空 + 标 unknown,不估算冒充。

R6
原文进证据,加工在派生层

换算/归一化只在派生层,规则写明可复算。

R7
事实与分析分开

对比/判断单独存放,标注"这是解读"。

R8
冲突不静默

多源打架都记下 + 标 conflict,不私自抹一方。

怎么触发

装了 /factcheck skill(.claude/skills/factcheck)后,语音或键入即可起一个 case。skill 会读 WORKFLOW + 对应 CASE.md 并按三阶段执行。

# 核一篇文章里的事实断言
/factcheck article https://example.com/some-article

# 核一条传闻 / 核某产品规格 / 收集模型价格
/factcheck news "某公司将于下月收购某某"
/factcheck product "某型号显卡"
